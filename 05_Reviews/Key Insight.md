### KQ-04: CONTROL LAYER - The Four Switches & The Handoff

**Source:** Log 011 - The Control Layers
**Gate:** 04 - Architecture
**Rule #12:** The control layer isn't a person you can appeal to, it is a chain of automated systems, each holding only part of the picture. Therefore: Prepare for the handoff between systems - not just the systems themselves.

**Core Pattern:**
Internet didn't remove borders. It automated them. No single decision-maker behind interface. Chain of specialized systems, each with own rules, each seeing only part.

**The Four Switches:**
1.  **Identity:** Are you who you claim to be? (OCR, liveness, sanctions screening, doc verification)
2.  **Liquidity:** Is this money safe to move? (Volume, velocity, geo-signals, chargeback risk)
3.  **Clearing:** Can this payment settle? (Intermediary banks, FX, correspondent relationships, compliance)
4.  **Access:** Should account remain open? (Login patterns, device reputation, behavioral anomalies)

**The Real Friction:** Not inside switches. In the handoff between them.
Payment anomaly → triggers ID check → ID check struggles → payout pending → behavior changes → security layer flags → account restriction → Support is next gate.

No villain required. Systems doing what designed to do, none with full context = cascade.

**The Kenyan Question (Field Research Thread):**
> When a national ID document changes, how quickly do international verification systems update their libraries, models, and validation pathways?

Valid document exists. Person exists. System exists. Do all three recognize one another? Gap = operator experiences as verification failure.

**Playbook:**
- Keep identity layer ready before request hits
- Build consistent operating history (risk systems love patterns)
- Treat payment platforms as pipes, not banks
- Keep records: contracts, invoices, confirmations, IDs
- When one switch fires, ask: Which other systems receive info from this event?
